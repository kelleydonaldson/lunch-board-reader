## H5 asterisk — the one real finding

Twice (run 1 attempt 1, run 2 attempt 1) the API returned
`finish_reason: "length"` with **null content**: the model spent the
entire 4096-token completion budget on reasoning (4,094 reasoning
tokens both times) and never produced an answer. Both runs passed on
their single allowed retry; run 3 passed first try (still 3,340
reasoning tokens). When the model does answer, the answer is exactly
right — joint header verbatim, both stops, no merge, no drop. The
collab graphic is simply the one input that makes the model think
hard enough to hit the seam's `--max-tokens 4096` ceiling. In
production terms this is a latency/reliability note, not a
correctness failure: the failure mode is an empty response (which the
guardrails/harness surface as an error), never a wrong or invented
board entry. Raw responses for both failed attempts are archived
under `out/run-1/` and `out/run-2/` (`*-attempt1-raw-response.json`).

## H6 pre-run gate — PASSED before the first H6 call

Per the owner's ruling, before H6 ran live, a synthetic extraction
identical in shape to the H6 expectation but with `end` `"2"` was fed
through the reader's guardrails via the simulate/no-API path in a
scratch copy of the demo store. Result: filed as **FLAG**
(entry fmvpp80otmoq) with the flag line "stop 1: end time '2' cannot
be parsed"; drafts count unchanged; zero drafts created. So
acceptable read (a) is safe end-to-end: a verbatim `"2"` can never
reach the board — a human sees it in the flag pile. All three live
H6 runs then returned exactly that shape.
